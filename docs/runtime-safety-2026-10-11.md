# 런타임 안전성 개선과 재발 방지 (2026-10-11)

전체 코드 검토에서 확인한 29개 문제를 배포, 권한, 금액 처리, 자원 제한, 알림 복구 경로에 반영했다. 아래 번호는 검토 결과와 대응을 연결한다. 테스트 통과는 실제 음성 품질이나 모든 외부 서비스 장애 상황의 검증을 의미하지 않는다.

## 배포와 DB 계약

Jenkins는 Secret text credential에서 `.env.deploy`를 복원하고 Compose의 `env_file`로 컨테이너 실행 환경을 전달한다. 이 주입 자체가 문제는 아니다. 복원한 파일이 이후 `COPY . /app`에 들어가는 경로가 별도 문제였다. 새로운 이미지 검사에서 파일이 발견되면 컨테이너 교체 전에 배포를 중단한다.

스키마 버전은 2이다. 기존 데이터 구조를 삭제하지 않고 `financial_locks`, `financial_operations`, `gambling_rounds`, `notification_deliveries`, `earthquake_pending`을 추가한다. `scripts.migrate_db`를 앱 시작 전에 실행해야 한다. readiness는 실제 DB 버전과 연결 상태를 확인한다.

금액 처리는 InnoDB 트랜잭션을 사용한다. 마이그레이션에서 관련 테이블의 엔진을 확인하고 필요한 경우 InnoDB로 변환한다. 봇은 단일 인스턴스로 운영한다. 시작 시 남은 예약 금액을 복원하므로 두 인스턴스를 동시에 시작하면 다른 인스턴스의 진행 중 게임을 복원할 수 있다. 이전 버전에서 이미 소실된 메모리 베팅은 복구할 수 없다.

롤백은 앱 이미지 복구이며 DB 마이그레이션을 되돌리지 않는다. 이번 변경은 테이블 추가를 사용한다. 롤백 이후에도 이번 배포 실패를 성공으로 바꾸지 않으며, 이전 이미지도 health 확인에 실패하면 운영자 조치가 필요하다는 로그를 남긴다.

## 알림 전송의 모호한 실패

Codex, Tibo, YouTube, 게임 공지, 기념일, DDAY, 주간 집계, 지진과 예약 전송은 안정적인 키를 사용한다. 지진 수정 및 임계값 상승 시 대체 메시지는 최초 전송과 다른 키를 사용한다.

[Discord 공식 메시지 API](https://github.com/discord/discord-api-docs/blob/main/developers/resources/message.mdx)의 `enforce_nonce`는 최근 몇 분의 중복을 방지한다. discord.py의 일반 send 인터페이스에는 이 옵션이 없으므로 해당 HTTP 어댑터에서만 설정하며 JSON과 파일 첨부 경로를 테스트한다.

DB 기록 전에 Discord 전송이 성공했을 수 있는 경우 채널 이력 100개에서 원문 내용과 봇 작성자를 확인한다. 원래 시도가 2분을 넘겼고 메시지를 찾을 수 없으면 자동 재전송을 중단한다. 중복 방지가 우선이므로 이 상태는 완전한 자동 복구가 아니다.

운영자는 `notification_deliveries`의 해당 channel, payload와 실제 채널을 비교해야 한다. 전송됐다면 message_id를 기록하고 lease를 해제한다. 전송되지 않은 것이 확인된 경우에만 attempted_at과 lease_until을 비워 재시도를 허용한다. 확인 없이 행을 지우면 중복 알림을 만들 수 있다. 대기와 실패는 로그에 남으며 다른 이벤트는 독립된 키로 처리한다.

[EMSC 공식 API](https://www.seismicportal.eu/fdsnws/event/1/redoc)의 offset은 1부터 시작하며 limit과 함께 페이지를 조회한다. EMSC 커서는 모든 페이지가 정상 조회되고 이벤트가 pending에 저장된 뒤에만 전진한다. 최초 커서가 없으면 최근 24시간을 조회한다. 제공자가 수정 이력을 보관하지 않거나 EEW 유효 시간이 지난 경우 모든 과거 알림의 복구를 보장하지 않는다. 일본 EEW의 오래된 최초 알림은 기존 freshness 정책으로 제외한다.

## 회귀 테스트와 확인 범위

로컬 Python 3.11에서 전체 unittest 859개가 통과했고 문법 검사와 변경 파일의 공백 검사가 통과했다. 기존 811개에서 재발 방지 테스트 48개를 추가했다. Jenkins 및 실제 컨테이너 결과는 해당 배포 빌드에서 별도로 확인해야 한다.

- `test_safety_regressions.py`: 실제 async 잔액 인터페이스, 송금 보존과 롤백, 일일 지급 실패, 블랙잭 중복 더블다운 및 환불, 뿌리기 환불, 권한과 URL, 준비 상태, 긴 출력, await 정책.
- `test_runtime_transactions.py`: DB 커밋 및 롤백, 취소와 타임아웃, 자식 task 연결 분리, 알림 완료와 lease, 전송 기록 복구, 모호한 실패 차단, View 종료 지연.
- `test_runtime_boundaries.py`: EMSC 페이지와 실패 커서, 5초 발화와 포화 작업 제한, 음성 연결 상호 배제, 최신 pending 유지, 고정 주간 집계, 요약 취소 후 슬롯 유지.
- `test_jenkins_deploy_script.py`: 의존 이미지 변경, 배포 실패 로그, 이전 이미지 복구와 복구 성공 후에도 실패 결과 유지.
- 기존 전체 unittest 및 Python 3.11 문법 검사도 수행한다. Jenkins에서 같은 테스트와 DB 마이그레이션, 이미지 비밀 파일 검사, 컨테이너 readiness를 다시 확인한다.

단위 테스트의 DB와 Discord 실패는 mock으로 재현한다. 실제 서버에서 동시 금액 부하, Discord 음성 청취, 최대 부하 메모리 및 실제 장애 강제 주입까지 검증한 것은 아니다. 과거 이미지의 비밀 파일 삭제와 이미 외부로 유출된 자격 증명 회전은 새 이미지 검사만으로 해결되지 않는다.
