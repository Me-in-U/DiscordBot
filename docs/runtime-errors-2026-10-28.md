# 음악 및 외부 수집 오류 처리

2026년 10월 26일부터 28일까지 보존된 실행 로그를 확인했다. 아래 수정은 소스에 반영했으며 테스트, 컴파일, 실제 Discord 재생, 서버 배포는 수행하지 않았다.

## 음악 검색과 즐겨찾기

즐겨찾기 검색 모달에서 예외가 2회 발생했다. 검색 결과 안내를 보내는 공통 함수가 후속 응답에 `view=None`을 전달해 discord.py에서 `TypeError`가 발생했다. 버튼이 없는 응답은 `view` 인자를 생략한다. 최초 응답에도 같은 규칙을 적용한다.

검색어에 항상 `ytsearch10:`을 붙이던 경로를 수정해 직접 입력한 YouTube 링크는 URL로 조회한다. 검색 결과의 상대 주소, 짧은 주소, `webpage_url`, 영상 ID를 정규화한다. YouTube Music 주소도 음악 URL 검사에서 허용한다. 외부 도메인과 채널 주소는 검색 결과 버튼으로 만들지 않는다.

검색 예외는 traceback을 기록하고 사용자에게 실패를 안내한다. 즐겨찾기 저장 실패도 안내하며, DB 조회 실패로 기존 캐시를 빈 목록으로 덮어쓰지 않는다. 저장 완료 후 패널 갱신 실패는 저장 실패와 구분한다.

## 음악 패널과 챕터

Discord 메시지 수정의 호출 제한 경고가 2,655회 있었다. 재생 중 진행 상태 수정 간격을 5초에서 15초로 늘렸다. 버튼 조작의 결과는 즉시 갱신한다. 실제 운영에서 호출 제한이 사라졌는지는 아직 확인하지 않았다.

yt-dlp가 제공하는 `chapters`의 제목과 시작 시각을 사용한다. 음수, 비정상 숫자, 곡 길이 이상의 위치와 중복 시작점은 제외한다. 현재 챕터를 임베드에 표시하고 이전/다음 버튼에 이동할 챕터 이름을 붙인다.

버튼 클릭 시 길드 잠금 안에서 현재 재생 위치와 이동 대상을 다시 계산한다. 이전 곡의 버튼은 곡이 교체되면 이동을 실행하지 않는다. 같은 음성 채널의 사용자만 제어할 수 있다. 이동 후 일시정지 여부와 챕터 정보를 유지하며 기존 구간 이동의 재생 식별자 처리를 재사용한다. 챕터가 없는 영상과 실시간 방송에서는 버튼을 숨긴다.

음성 스트림 로그에는 TLS 읽기 실패와 조기 종료도 있었다. FFmpeg의 네트워크 오류 및 HTTP 429/5xx 재연결 옵션을 보완했다. 공급자가 스트림을 계속 거절하는 문제나 실제 음성 품질까지 해결됐다는 의미는 아니다.

## 외부 수집

| 로그 | 관찰과 처리 |
| --- | --- |
| 메이플스토리 목록 조회 실패 89회 | 일부 응답이 HTTP 점검 페이지로 이동한 뒤 403으로 실패했다. 해당 점검 호스트가 HTTP로 이동한 경우 HTTPS로 다시 요청한다. 일시적인 HTTP 오류와 연결 오류에는 제한된 재시도를 적용한다. |
| 로스트아크 목록 파싱 실패 80회 | 사이트 점검 시간대에 집중됐다. 현재 공식 공지 페이지는 정상 응답한다. HTTP 오류에는 재시도를 적용하고, 목록이 없는 응답은 페이지 제목을 오류에 포함한다. 실제 당시 HTML은 로그에 보존되지 않아 점검 페이지 여부는 확정하지 않는다. |
| 유튜브 커뮤니티 파싱 실패 3회 | 고정된 `var ytInitialData = ` 문자열에만 의존하던 파서를 게시물 요약과 공유한다. 공백 변경, 직접 대입, `window` 속성 대입을 지원한다. HTTP 오류에도 재시도를 적용한다. 당시 응답 HTML이 없어 실제 원인이 대입 형식 변경인지는 확정하지 않는다. |
| Tibo 조회 오류 6회 | HTTP 500과 타임아웃이 있었다. 연결 오류, 타임아웃, HTTP 408/429/500/502/503/504에는 최대 3회 요청한다. 재시도 한도를 넘으면 기존 실패 경로로 전달하며 알림 상태를 덮어쓰지 않는다. |

재시도 간격은 기본 1초와 2초다. `Retry-After`가 있으면 그 값을 따르며 30초를 넘는 대기는 다음 정기 조회에 맡긴다. 일반 403과 파싱 오류는 무조건 반복 요청하지 않는다. 실패 traceback은 유지한다. 공지 수집의 공통 로거는 실제 채널 종류를 표시해 로스트아크 실패를 메이플스토리 실패로 오인하지 않도록 한다.

MySQL의 `VALUES()` 사용 중단 경고는 같은 값을 UPDATE 매개변수로 다시 바인딩하는 방식으로 수정했다. 길드, 사용자, 채널 설정, 즐겨찾기, 공지 및 지진 상태 저장에 같은 방식을 적용한다. 특정 DB 버전의 행 별칭 문법을 요구하지 않는다. 지진 재시도 목록의 중복 등록은 `INSERT IGNORE` 대신 기본키를 그대로 유지하는 UPSERT로 처리해 중복 경고를 없애고 다른 DB 오류는 숨기지 않는다.

사이트 점검, 외부 서버의 지속적인 장애, Discord 및 음성 연결 재개를 봇 소스만으로 없앨 수는 없다. 라이브러리의 Python 지원 종료 예고와 자동 시간 보정 메시지는 기능 예외와 구분했다. 이 메시지를 숨기거나 Python 실행 버전을 변경하지 않았다.

## 작성한 회귀 테스트

- `test_music_runtime_errors.py`: 버튼 없는 응답, 링크 검색, 검색 실패, DB 저장 및 캐시 실패
- `test_music_chapters.py`: 외부 챕터 값, 순서와 경계, 버튼 이름과 비활성화, 임베드
- `test_music_lifecycle_regressions.py`: 클릭 시점 이동, 오래된 버튼, 음성 채널 제한, 일시정지 유지
- `test_http_retry.py`: 일시 오류 회복, 재시도 한도, 일반 403, 호출 제한 대기, 취소 전파
- `test_upstream_parsing_regressions.py`: 유튜브 대입 형식, 잘못된 HTML, 점검 페이지 HTTPS 이동, 로스트아크 진단
- `test_upsert_bindings.py`: INSERT와 UPDATE에 같은 값이 바인딩되는지 확인

기존 검색 및 Tibo 테스트의 기대값도 변경된 동작에 맞췄다. 테스트는 작성만 했으며 실행 결과는 미확인이다.
